# Servers

Οι λογαριασμοί φιλοξενίας δημιουργούνται στους servers σου μέσω του API του panel τους. Το GaiaCP δουλεύει με
**cPanel / WHM**, **Plesk**, **HestiaCP** και **DirectAdmin**· το καθένα είναι πρόσθετο, οπότε κλείσε όσα δεν
χρησιμοποιείς στις Ρυθμίσεις → Πρόσθετα. Υπάρχει και το **CyberPanel**, καθώς και το **Proxmox VE** για VPS, κλειστά μέχρι να τα ανοίξεις στις Ρυθμίσεις →
Πρόσθετα. Οι servers είναι στις Ρυθμίσεις → Προϊόντα και domains → **Servers** (μόνο για υπερδιαχειριστές).

## Νέος server

Συμπλήρωσε όνομα, τύπο, hostname και θύρα, και μετά τη σύνδεση στο API. Τα στοιχεία σύνδεσης αποθηκεύονται
κρυπτογραφημένα και δεν ξαναφαίνονται: άφησε το πεδίο κενό για να κρατήσεις το τρέχον. Πάτα **Δοκιμή σύνδεσης**: δείχνει
την έκδοση του panel και τα πακέτα που βρήκε.

| Panel | Θύρα | Σύνδεση |
|---|---|---|
| cPanel / WHM | 2087 | `root` ή reseller, με API token (WHM → Development → Manage API Tokens) |
| Plesk | 8443 | το login και ο κωδικός του admin, ή κενό login και secret key (`plesk bin secret_key -c -ip-address <IP του GaiaCP>`) |
| HestiaCP | 8083 | κενό login και access key ως `ACCESS_KEY:SECRET_KEY` (επίτρεψε πρώτα το API και την IP του GaiaCP) |
| DirectAdmin | 2222 | ο admin ή reseller, με login key που επιτρέπεται να χρησιμοποιεί το API |
| CyberPanel | 8090 | ο `admin` και ο κωδικός του, με ενεργή πρόσβαση API (Users → API Access) και κλειστή επαλήθευση δύο βημάτων |
| Enhance | 443 | το ID του οργανισμού σου ως username, με access token (Settings → Access tokens) |
| Proxmox VE | 8006 | το ID του API token (`root@pam!gaiacp`) και το secret του (Datacenter → Permissions → API Tokens, χωρίς Privilege Separation) |

Τα περισσότερα panels απαντούν μόνο στις διευθύνσεις IP που επιτρέπεις: επίτρεψε τη διεύθυνση του server του GaiaCP.
Ο **Έλεγχος πιστοποιητικού TLS** κλείνει μόνο για server που έχει ακόμα αυτο-υπογεγραμμένο πιστοποιητικό· ξανάνοιξέ
τον μόλις αποκτήσει κανονικό.

Τα προαιρετικά πεδία **Χωρητικότητα και κόστος** βοηθούν στη διαχείριση των servers:

- **Μέγιστοι λογαριασμοί**: η λίστα Servers δείχνει τους λογαριασμούς απέναντι σε αυτό («33/120») και οι νέες
  παραγγελίες παρακάμπτουν τον γεμάτο server.
- **Μηνιαίο κόστος**: οι Αναφορές → Πρόβλεψη εσόδων και Έσοδα ανά server δείχνουν το κέρδος μετά από αυτό.
- **Διεύθυνση IP**: για νέους λογαριασμούς όπου το panel τη χρειάζεται, για τον Έλεγχο sites και τον έλεγχο IP σε
  blacklists.
- **URL σελίδας κατάστασης**: ανοίγει από τη λίστα Servers.

Η **Σύνδεση** στη λίστα Servers ανοίγει το panel ήδη συνδεδεμένο (σε HestiaCP, DirectAdmin, CyberPanel και Enhance, τη σελίδα
σύνδεσής του).

Στο CyberPanel ένας λογαριασμός φιλοξενίας είναι ένα **website** (το domain της υπηρεσίας) που ανήκει σε χρήστη
CyberPanel με το username της υπηρεσίας· ο κωδικός είναι η σύνδεση αυτού του χρήστη στο CyberPanel. Τα πακέτα
φαίνονται σαν `admin_Default`. Τα νέα websites ξεκινούν με την έκδοση PHP που διαλέγεις στις Ρυθμίσεις → Ενσωματώσεις →
**CyberPanel** (PHP 8.2 αν δεν την αλλάξεις).

### Enhance

Το πρόσθετο **Enhance** είναι κλειστό μέχρι να το ανοίξεις στις Ρυθμίσεις → Πρόσθετα. Ως hostname βάλε τη διεύθυνση
του control panel (π.χ. `cp.example.com`). Το πακέτο ενός προϊόντος φιλοξενίας είναι το όνομα ενός plan του Enhance.
Κάθε πελάτης γίνεται πελάτης (customer) στο Enhance με login το email του, και κάθε υπηρεσία φιλοξενίας μια συνδρομή στο
plan με ένα website για το domain της. Ο πελάτης έχει ένα login στο Enhance για όλες τις υπηρεσίες του σε αυτόν τον
server: ο κωδικός του είναι της πρώτης υπηρεσίας, και η **Αλλαγή κωδικού** τον αλλάζει για όλες. Η **Σύνδεση** στο
client area ανοίγει το Enhance ήδη συνδεδεμένο. Πελάτες και websites που έφτιαξες μόνος σου στο Enhance βρίσκονται από
το email του πελάτη και το domain. Φτιάχτηκε χωρίς πραγματικό server Enhance: δοκίμασε πρώτα τη Δοκιμή σύνδεσης και μία
παραγγελία.

## Σε ποιον server πάει ένας νέος λογαριασμός

Ένα προϊόν φιλοξενίας έχει τους **servers** που διαθέτουν το πακέτο του. Μια νέα παραγγελία, μια νέα υπηρεσία και μια
παραγγελία πελάτη πάνε στον λιγότερο γεμάτο ενεργό· οι γεμάτοι παρακάμπτονται και οι ανενεργοί δεν προσφέρονται ποτέ.
Η Νέα παραγγελία και η Ολοκλήρωση παραγγελίας σε αφήνουν να διαλέξεις άλλον. Όταν όλοι είναι γεμάτοι, το στήσιμο
σταματά και σου ζητά server.

## Το μενού Λογαριασμός

Η σελίδα μιας υπηρεσίας φιλοξενίας έχει μενού **Λογαριασμός**:

- **Δημιουργία στον server**: φτιάχνει τον λογαριασμό με το domain και το πακέτο της υπηρεσίας. Το όνομα χρήστη (από
  το domain) και ο κωδικός δημιουργούνται αν είναι κενά και κρατιούνται κρυπτογραφημένα στην υπηρεσία. Δουλεύει και σε
  ενεργό λογαριασμό, για να τον ξαναφτιάξεις σε άλλον server μετά από μεταφορά (ο παλιός server μένει ανέγγιχτος).
- **Αλλαγή πακέτου**, **Αλλαγή κωδικού**.
- **Αναστολή** και **Άρση αναστολής**: ρωτούν πρώτα το panel, οπότε δουλεύουν ακόμα κι αν η κατάσταση άλλαξε με το
  χέρι.
- **Τερματισμός**: σβήνει τον λογαριασμό και τα αρχεία του από τον server. Γράφεις το όνομα χρήστη για επιβεβαίωση.
- Σε VPS του Proxmox: **Εκκίνηση**, **Τερματισμός**, **Επανεκκίνηση** και **Αναγκαστική διακοπή** (κόβει το ρεύμα, για
  VPS που δεν αποκρίνεται πια).

Κάθε ενέργεια ρωτά πρώτα το panel για την τρέχουσα κατάσταση του λογαριασμού, οπότε η επανάληψή της ή μια νέα
προσπάθεια μετά από timeout δεν κάνει ζημιά. Όταν μια κλήση αποτύχει, η υπηρεσία μένει όπως ήταν, το σφάλμα φαίνεται
στην οθόνη, και μένει στο Αρχείο ενεργειών και στο Χρειάζονται προσοχή του πίνακα ελέγχου. Άνοιξε το Ρυθμίσεις →
Αρχεία καταγραφής → Καταγραφή → **Αρχείο modules** για να δεις κάθε αίτημα και απάντηση (με κρυμμένους κωδικούς) όταν
θέλεις να βρεις το γιατί.

Η ενότητα **Χρήση** στην υπηρεσία δείχνει τον χώρο στον δίσκο και το bandwidth του μήνα απέναντι στα όρια του
πακέτου, όπως τα διαβάζει από το panel.

## VPS σε Proxmox VE

Το πρόσθετο **Proxmox VE** είναι κλειστό μέχρι να το ανοίξεις στις Ρυθμίσεις → Πρόσθετα. Ένα VPS είναι υπηρεσία
φιλοξενίας σε server Proxmox:

- **Πακέτο = ένα template.** Στο Proxmox φτιάξε ένα KVM template με cloud-init για κάθε πλάνο (π.χ.
  `debian12-2cpu-4gb`) και βάλε το όνομά του ως πακέτο του προϊόντος· η Δοκιμή σύνδεσης δείχνει τα templates που βρήκε.
  Ένα νέο VPS είναι πλήρες αντίγραφό του, με τη CPU, τη μνήμη και τον δίσκο του, στο node του template. Η αλλαγή
  πακέτου παίρνει τη CPU και τη μνήμη του νέου template (ισχύουν από τον επόμενο τερματισμό και εκκίνηση) και μεγαλώνει
  τον δίσκο στο μέγεθός του· ο δίσκος δεν μικραίνει ποτέ.
- **Διεύθυνση.** Οι Ρυθμίσεις → Proxmox → **Διευθύνσεις IP** κρατούν τις διευθύνσεις κάθε server: ένα νέο VPS παίρνει
  την πρώτη ελεύθερη και την επιστρέφει όταν διαγραφεί. Ένας server χωρίς διευθύνσεις εκεί δίνει διεύθυνση με DHCP.
- **Κωδικός.** Το cloud-init δίνει τον κωδικό της υπηρεσίας στον χρήστη σύνδεσης (root, ή όποιον ορίσεις στις
  Ρυθμίσεις → Proxmox). Η Αλλαγή κωδικού τον ορίζει για την επόμενη εκκίνηση, και αμέσως αν το VPS έχει τον QEMU guest
  agent.
- **Ο πελάτης** παίρνει χρήστη στο Proxmox με το όνομα χρήστη και τον κωδικό της υπηρεσίας, που βλέπει μόνο το VPS του
  (ρόλος PVEVMUser αρχικά). Η Σύνδεση στη σελίδα της υπηρεσίας του ανοίγει το Proxmox, όπου βρίσκει την κονσόλα. Η
  Εκκίνηση, ο Τερματισμός και η Επανεκκίνηση είναι κι αυτά στη σελίδα της υπηρεσίας του, εκτός αν τα κλείσεις στις
  Ρυθμίσεις → Proxmox.
- **Η Αναστολή** σβήνει το VPS και κλειδώνει τον χρήστη του πελάτη στο Proxmox· **ο Τερματισμός** διαγράφει το VPS με
  τους δίσκους του, τον χρήστη, και ελευθερώνει τη διεύθυνσή του.

Το GaiaCP ξαναβρίσκει κάθε VPS από τα tags του στο Proxmox (`gaiacp`, `gaiacp-user-<όνομα χρήστη>`): μην τα σβήσεις.

## Σύγκριση με τον server

Η **Σύγκριση με τον server** (στη σελίδα του server) διαβάζει κάθε λογαριασμό στο panel και δείχνει ό,τι δεν
ταιριάζει με το GaiaCP: λογαριασμούς μόνο στον server (ξεχασμένους ή που δεν χρεώθηκαν ποτέ), υπηρεσίες που ο server
δεν έχει, και διαφορές σε αναστολή, πακέτο ή domain. Κάθε γραμμή έχει διόρθωση με ένα κλικ, στον server ή μόνο στο
GaiaCP· διαγραφή λογαριασμού δεν προσφέρεται ποτέ. Σημείωσε όσους λογαριασμούς φιλοξενείς δωρεάν ως **Χωρίς χρέωση,
σκόπιμα** με μια σημείωση, και η **Προσθήκη στο GaiaCP** κάνει έναν λογαριασμό χωρίς χρέωση υπηρεσία. Με τη Νυχτερινή
σύγκριση servers ανοιχτή στις Ρυθμίσεις → Αυτοματισμοί, το καμπανάκι σου λέει κάθε πρωί τις νέες διαφορές.

## Παρακολούθηση

Σύνδεσε κάθε server με το monitor του σε μια υπηρεσία uptime για να βλέπεις αν είναι πάνω: **Uptime Kuma**,
**UptimeRobot**, **HetrixTools** ή **Better Stack** (το καθένα πρόσθετο με δική του σελίδα ρυθμίσεων στις
Διασυνδέσεις, όπου βάζεις το κλειδί API). Στον server, διάλεξε την υπηρεσία παρακολούθησης και το monitor. Κάθε 5
λεπτά το GaiaCP διαβάζει την κατάσταση:

- η λίστα Servers δείχνει Σε λειτουργία / Εκτός λειτουργίας / Σε αναμονή / Συντήρηση και μπάρα uptime για 24 ώρες ή 30 ημέρες·
- η κάρτα Servers του πίνακα ελέγχου δείχνει τα ίδια·
- οι υπερδιαχειριστές παίρνουν καμπανάκι όταν ένας server πέφτει και όταν επανέρχεται·
- οι πελάτες με υπηρεσίες σε αυτόν βλέπουν μήνυμα πάνω στην περιοχή πελατών όσο είναι κάτω ή σε συντήρηση (Ρυθμίσεις →
  Περιοχή πελατών → Προβλήματα server, με δικό σου μήνυμα).

Δύο ακόμα πρόσθετα προσέχουν τους servers σου:

- Ο **Έλεγχος IP σε blacklists** ψάχνει την IP κάθε ενεργού server σε λίστες spam (Spamhaus, SpamCop, Barracuda, PSBL)
  κάθε ώρα και χτυπά το καμπανάκι όταν μπει ή βγει από μία.
- Ο **Έλεγχος sites** ελέγχει κάθε μέρα ότι το domain κάθε ενεργού λογαριασμού φιλοξενίας δείχνει ακόμα στον server
  του και ότι το πιστοποιητικό HTTPS του είναι έγκυρο και δεν λήγει σύντομα. Τα προβλήματα φαίνονται στις Υπηρεσίες →
  **Έλεγχος sites** και πάνε μία φορά στο καμπανάκι.
